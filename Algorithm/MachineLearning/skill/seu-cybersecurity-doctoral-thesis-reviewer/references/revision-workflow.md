# 审核结果驱动的论文修改工作流

本流程适用于已有审核报告、外审意见、导师批注或上一轮问题清单。目标是将“意见”转换为可追踪的论文修改和证据补全任务。它不允许用虚构内容填补实验、数据、创新性或作者事实。

## 1. 输入解析

接受以下输入组合：

- 论文原文及章节/段落定位；
- 审核报告（表格、Markdown、Word/PDF 导出文本）；
- 评审意见原文；
- 导师批注或修改清单；
- 学校/学院格式模板和版本信息；
- 实验数据、图表源文件、代码、日志或参考文献库。

如果只有审核意见，没有论文原文：

1. 解析意见并生成修改任务；
2. 提供候选替换段落、补证据计划和需要定位的范围；
3. 明确标注“尚未写回论文”，不声称修改完成。

如果只有论文原文，没有审核意见：使用全文审核模式，不假设存在上一轮问题。

## 2. 审核项标准化

将每条意见转换为以下记录：

```yaml
issue_id: R-001
source: "外审意见第 3 条 / 审核报告"
location: "第 4 章 4.2.3，表 4-6 前一段"
severity: "阻断项 | 高优先级 | 一般项"
category: "技术 | 证据 | 结构 | 表达 | 格式 | 引用 | 学术诚信"
finding: "可核验的问题描述"
impact: "对论文结论、答辩或规范的影响"
evidence: ["原文引句", "图表/实验/模板位置"]
action: "修改文字 | 重组章节 | 补实验 | 补引用 | 格式修复 | 请求确认"
status: "待处理"
```

若意见含糊，例如“创新性不足”“实验不充分”“逻辑不清”，先拆成可验证子问题，不直接对全文进行无差别重写。无法定位的意见状态为 `待定位`，需要用户提供范围或允许全文搜索。

## 3. 修改决策矩阵

| 类型 | 默认动作 | 是否可直接写回 |
|---|---|---:|
| 错别字、标点、明显语病 | 最小编辑 | 是，仍需记录 |
| 术语、缩写、符号不一致 | 建立术语表后统一 | 是，需全文回归 |
| 图表/章节/公式交叉引用错误 | 修正引用和编号 | 是，需验证目标存在 |
| 有原文证据支持但表达过强 | 收敛措辞，降低断言强度 | 通常是 |
| 方法描述不完整但事实明确 | 补充已有实现信息 | 需确认事实来源 |
| 威胁模型或安全边界改变 | 提供候选方案 | 否，作者/导师确认 |
| 研究贡献、创新性或作者贡献 | 重写论证结构 | 否，不能代作者决定 |
| 缺实验、缺数据、缺性能结果 | 生成补实验任务和占位符 | 否 |
| 统计结果、数值、图表趋势 | 只使用用户提供或可复核数据 | 否，禁止猜测 |
| 缺失或疑似错误引用 | 标记核验任务 | 否，禁止编造文献 |
| 当届东南大学格式要求 | 按用户提供模板修复 | 只有模板可核验时 |

## 4. 逐项修改步骤

对每一条审核项执行：

1. 找到原文和上下文，读取该节标题、前后段、相关图表和引用。
2. 记录原文证据和问题边界，判断审核意见是否成立、部分成立或缺少依据。
3. 选择最小修改范围，避免只为一个问题重写无关章节。
4. 生成改稿，并标记新增、删除、重排和待确认内容。
5. 检查改稿是否引入新事实、绝对结论、未经证实的数字或新引用。
6. 更新问题状态和“修改位置 -> 审核项”映射。
7. 对需要补实验/数据/作者确认的项生成明确的下一步，不标记为已完成。

## 5. 改稿标记方式

### Markdown/纯文本/LaTeX

优先生成补丁或新文件，例如：

```text
thesis-v3.tex              # 原文件保留
thesis-v3.revised.tex      # 修改稿
thesis-v3.revision-log.md  # 修改记录
```

对关键改动使用统一标记：

```text
[修改 R-001：补充威胁模型边界]
[待作者确认：攻击者是否具备管理员权限？]
[待补实验：需要 5 次独立运行的均值和置信区间]
```

正式交付时，可根据用户需要移除内部标记，但不能丢失修改日志。

### Word/PDF

如果具备可靠的文档编辑工具，优先使用修订/批注。PDF 通常不适合作为直接修改源文件：先提取文本并确认版式限制；不能可靠保留公式、图表或页码时，交付修改稿文本和定位清单，而不是声称已完成排版修改。

## 6. 工程博士论文的修改重点

- 将“创新性不足”转化为：基线、差距、技术贡献、工程约束和实验支持的对应关系；不能凭空增加创新点。
- 将“工程价值不明显”转化为：部署环境、系统边界、资源约束、接口、兼容性、维护成本、故障和推广条件；只能使用作者提供的真实信息。
- 将“安全性论证不足”转化为：威胁模型、攻击者能力、安全目标、机制映射、攻击实验和残余风险；不能把未验证的安全声明改写成已证明。
- 将“实验不充分”转化为可执行矩阵：研究问题、指标、基线、数据、环境、重复次数、统计方法、预期输出和责任人。
- 将“逻辑不清”转化为章节/段落重排和过渡语句，但不通过增加术语或空泛总结掩盖技术缺口。

## 7. 修改日志格式

```text
| issue_id | 原位置 | 修改位置 | 原问题 | 修改动作 | 状态 | 证据/待办 |
| R-001 | 第4章4.2.3 | 第4章4.2.3 | 威胁模型未定义管理员权限 | 增加权限边界段落 | 待作者确认 | 需确认真实部署角色 |
| R-002 | 表4-6 | 表4-6 | 缺少重复实验说明 | 增加实验设计说明占位符 | 待补实验/数据 | 需提供原始日志 |
```

状态含义：

- `已修改`：文字/结构已经完成，并通过相关回归检查；
- `部分修改`：能修改的内容已完成，仍有依赖数据或作者决定的部分；
- `待作者确认`：候选改稿已给出，但事实、边界或取舍不能由模型决定；
- `待补实验/数据`：当前证据不足，已生成实验或数据任务；
- `不采纳（说明理由）`：明确记录不采纳原因，不删除原审核意见。

## 8. 回归检查

修改完成后至少检查：

1. 每个已修改审核项是否有对应位置和状态；
2. 摘要、贡献、章节小结和结论是否与改稿一致；
3. 新增技术断言是否有原文、实验、代码、日志或引用支撑；
4. 威胁模型变化是否同步影响方案、实验和局限性；
5. 图、表、公式、章节和参考文献交叉引用是否有效；
6. 术语、缩写、变量、单位和版本号是否一致；
7. 所有 `[待补...]`、`[待确认...]` 项是否列入交付清单；
8. 是否误把建议性修改写成东南大学硬性要求；
9. 是否出现虚构数据、虚构引用、无依据的“显著提升”或删除不利结果的表述。

## 9. 最终交付

当用户要求直接修改论文且已提供原文和授权时，交付：

1. 新版本论文或可应用补丁；
2. 修改日志；
3. 审核项映射表；
4. 未完成事项和补证据任务；
5. 回归检查结果；
6. 需要作者/导师确认的决策列表。

如果用户未授权写回文件，交付候选改稿和补丁，不执行覆盖。任何无法可靠解析或修改的文件格式都要明确说明。
